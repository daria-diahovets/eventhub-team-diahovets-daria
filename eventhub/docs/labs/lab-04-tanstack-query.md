## 1. Мета роботи

Перетворити каталог із демонстрації на робочий варіант, яким можна користуватися: з фільтрами, гортанням, осмисленими станами й без зайвих запитів.

Після виконання студент уміє:

- відрізняти серверний стан від стану застосунку й тримати їх окремо;
- будувати ключі запитів так, щоб кеш адресувався правильно;
- реалізувати нескінченне гортання поверх курсорної пагінації;
- тримати фільтри в URL замість `useState`;
- показувати чотири стани екрана, а не два.

## 4. Крок 1. Підключення

```bash
pnpm --filter web add @tanstack/react-query react-router-dom
pnpm --filter web add -D @tanstack/react-query-devtools
```

`apps/web/src/main.tsx`:

```tsx
const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      staleTime: 30_000,
      retry: 2,
      refetchOnWindowFocus: true,
    },
  },
});

createRoot(root).render(
  <StrictMode>
    <QueryClientProvider client={queryClient}>
      <BrowserRouter>
        <App />
      </BrowserRouter>
      <ReactQueryDevtools initialIsOpen={false} />
    </QueryClientProvider>
  </StrictMode>,
);
```

**`staleTime: 30_000`** – скільки часу дані вважаються свіжими. Поки він не минув, повторний перехід на сторінку не піде в мережу взагалі.

Питання, на яке відповідає це число: скільки часу застарілі дані ще прийнятні? Для каталогу подій – десятки секунд. Для залишку вільних місць у тижні 7 буде нуль. Для довідника міст – година.

**`retry: 2`** – три спроби разом із першою, з наростаючою затримкою. Мережа моргнула – користувач цього не помітить. Порівняйте з версією на `useEffect`, де той самий збій давав порожній екран назавжди.

**`gcTime`** – не потрібно змінювати. П'ять хвилин за замовчуванням – це скільки неактивний запис лишається в пам'яті, перш ніж його приберуть. Плутати `staleTime` і `gcTime` – класика; перший про свіжість, другий про прибирання.

## 5. Крок 2. Список на `useQuery`

### 5.1. Обгортка над клієнтом

`apps/web/src/api/queries.ts`:

```ts
export async function fetchEvents(
  filters: CatalogFilters,
  cursor?: string | undefined,
): Promise<EventPage> {
  const { data, error } = await api.GET("/events", {
    params: {
      query: {
        ...(filters.city ? { city: filters.city } : {}),
        ...(filters.from ? { from: filters.from } : {}),
        ...(cursor ? { cursor } : {}),
        limit: PAGE_SIZE,
      },
    },
  });
  if (error) throw error; // ← найважливіший рядок файлу
  return data;
}
```

**`throw error`** – важливе. `openapi-fetch` повертає помилку значенням, а TanStack Query розпізнає лише викинуту. Без цього рядка `isError` ніколи не стане `true`: 404 виглядатиме як успішна відповідь із `data === undefined`, і застосунок впаде на `data.items`.

Це найчастіша помилка, яку допускають в даній роботі, і знайти її важко саме тому, що симптом з'являється далеко від причини.

### 5.2. Ключі

`apps/web/src/api/queryKeys.ts`:

```ts
export const eventKeys = {
  all: ["events"] as const,
  list: (filters: CatalogFilters) => ["events", "list", filters] as const,
  detail: (eventId: string) => ["events", "detail", eventId] as const,
};
```

**Чому фабрика, а не рядки в компонентах.** Поки ключів три, різниці немає.

Спільний префікс `["events"]` у списку й у деталях – не випадковість. Одна інвалідація накриє обидва. В подальшому розвитку роботи після бронювання зміниться і кількість вільних місць у списку, і вона ж на сторінці події.

### 5.3. Компонент

```tsx
const { data, isPending, isError, error } = useQuery({
  queryKey: eventKeys.list(filters),
  queryFn: () => fetchEvents(filters),
});
```

## 6. Крок 3. Чотири стани

Екран із даними має чотири стани, а не два. Три з них зазвичай забувають описати, зверніть на них увагу.

```tsx
if (isPending) return <EventListSkeleton />;
if (isError) return <ErrorState error={error} onRetry={() => void refetch()} />;
if (events.length === 0) return <EmptyState ... />;
return <ul>…</ul>;
```

**Завантаження – скелетон, а не спінер.** Скелетон повторює структуру майбутнього вмісту: три прямокутники на місці трьох карток. Спінер по центру не відповідає на питання «що саме завантажується».

**Порожньо – не помилка.** Показувати тут повідомлення про збій означає вводити користувача в оману: система відпрацювала правильно, просто під фільтр нічого не підпало. Інший колір, інший текст і – обов'язково – дія, яка вирішує проблему: «Скинути фільтри».

Але кнопку скидання показуйте лише тоді, коли фільтри справді застосовані. Порожній каталог без фільтрів – інша ситуація.

**Помилка – текст із `problem+json`.** Поле `title` тієї самої відповіді, яку ваш бекенд віддає з роботи №2:

```ts
function titleOf(error: unknown): string {
  if (typeof error === "object" && error !== null && "title" in error) {
    return String((error as Problem).title);
  }
  return "Не вдалося завантажити дані";
}
```

Саме тому в контракті `title` призначений людині, а машинне рішення приймається за стабільним `type`.

## 7. Крок 4. Фільтри в URL

### 7.1. Хук

`apps/web/src/features/catalog/useCatalogFilters.ts`:

```ts
export function useCatalogFilters() {
  const [params, setParams] = useSearchParams();

  const filters: CatalogFilters = useMemo(
    () => ({
      city: params.get("city") ?? undefined,
      from: params.get("from") ?? undefined,
    }),
    [params],
  );

  const setFilter = useCallback((key, value) => {
    setParams((prev) => {
      const next = new URLSearchParams(prev);
      if (value) next.set(key, value); else next.delete(key);
      return next;
    });
  }, [setParams]);

  return { filters, setFilter, reset, isEmpty };
}
```

### Чому не `useState`

| `useState` | `useSearchParams` |
|------------|-------------------|
| Посилання на відфільтрований каталог надіслати неможливо | Посилання відтворює точно той самий екран |
| Кнопка «назад» скидає фільтр | Історія браузера працює безкоштовно |
| Перезавантаження втрачає вибір | Стан переживає перезавантаження |
| Стан дублюється: він і в компоненті, і в `queryKey` | Одне джерело правди |

### 7.2. Фільтри в ключі

```tsx
const { data } = useQuery({
  queryKey: eventKeys.list(filters), // ← фільтри тут
  queryFn: () => fetchEvents(filters),
});
```

**Правило** – якщо значення використовується всередині `queryFn` – воно повинно бути в `queryKey`.

Порушення дає найпідступніший симптом роботи: перший вибір міста працює, другий – ні. Застосунок запитує правильні дані, а показує ті, що вже лежать у кеші під старою адресою.

### 7.3. Гонка відповідей зникає сама

Згадайте проблему з роботи №1: швидко змінили фільтр, прийшла відповідь на старий запит і затерла новий.

Тепер цього не може статися. Відповідь на старий ключ потрапить у свій запис кеша, який ніхто не показує. В роботі не додавали захисту, це виконано за рахунок архітектурного рішення, архітектура не залишила місця, де помилка могла б виникнути.

## 8. Крок 5. Нескінченне гортання

Поле `nextCursor`, яке реалізоване в роботі №1, стає кнопкою.

```tsx
const {
  data, fetchNextPage, hasNextPage, isFetchingNextPage,
} = useInfiniteQuery({
  queryKey: eventKeys.list(filters),
  queryFn: ({ pageParam }) => fetchEvents(filters, pageParam),
  initialPageParam: undefined as string | undefined,
  getNextPageParam: (lastPage) => lastPage.nextCursor ?? undefined,
});

const events = data.pages.flatMap((page) => page.items);

{hasNextPage && (
  <button disabled={isFetchingNextPage} onClick={() => void fetchNextPage()}>
    {isFetchingNextPage ? "Завантаження…" : "Показати ще"}
  </button>
)}
```

**`getNextPageParam`** – єдине місце застосунку, де фронтенд знає про курсор. Повернули `undefined` – `hasNextPage` стане `false`, і кнопка зникне сама. Рахувати елементи не треба.

**`data.pages`** – масив сторінок, а не масив подій. Кеш зберігає структуру відповідей.

**`nextCursor ?? undefined`** – `null` у контракті означає «сторінок більше немає». Саме тому його тип був `[string, "null"]`.

**`disabled` під час завантаження** – інакше подвійний клік створить два запити на ту саму сторінку й дублі в списку.

**Курсор ніде не розбирається.** Якщо вам захотілося зробити `atob(cursor)`, щоб «дізнатися дату» – зупиніться: ADR-001 оголошує курсор непрозорим для клієнта. Щойно хтось почне його розбирати, змінити ключ сортування на бекенді стане неможливо.

Поставте `PAGE_SIZE = 6`: із десятьма подіями в сидах це дає дві сторінки, і гортання видно.

## 9. Крок 6. Сторінка події та перевірка гонки

### 9.1. Окремий запит

```tsx
const { eventId } = useParams<{ eventId: string }>();

const { data, isPending, isError } = useQuery({
  queryKey: eventKeys.detail(eventId ?? ""),
  queryFn: () => fetchEvent(eventId!),
  enabled: Boolean(eventId),
});
```

**`enabled`** не дає піти запиту з порожнім ідентифікатором. Без цього рядка буде отримано 400 – і з боку користувача це виглядатиме як помилка застосунку, хоча насправді це просто некоректний маршрут.

Додайте посилання з картки списку на `/events/:eventId` і кнопку «До каталогу» назад.

### 9.2. Перевірка гонки

У DevTools → Network увімкніть повільну мережу (Slow 3G). Швидко натисніть «Львів», потім «Київ».

Має бути показано київські події. Якщо львівські – фільтр не потрапив у `queryKey`.

## 10. Критерії приймання

| № | Критерій | Перевірка |
|---|----------|-----------|
| 1 | Посилання з фільтрами відтворює екран | копіювання адреси в іншу вкладку |
| 2 | Кнопка «назад» знімає фільтр | браузер |
| 3 | Окремий запис кеша на кожен набір фільтрів | Devtools |
| 4 | Чотири стани екрана реалізовані | вимкнути бекенд, порожній фільтр |
| 5 | Скелетон, а не спінер | візуально |
| 6 | Гортання працює, кнопка зникає на кінці | клікати до кінця |
| 7 | Курсор ніде не розбирається | `grep -rn "atob\|base64" apps/web/src` |
| 8 | Гонка не відтворюється | Slow 3G, швидке перемикання |
| 9 | Текст помилки з `problem+json` | зупинити бекенд |
| 10 | Повернення зі сторінки події без запиту | Network порожній |

## 11. Типові проблеми

**`isError` ніколи не `true`, застосунок падає на `data.items`**
Забуто `throw error` у `queryFn`.

**Перший вибір міста працює, другий – ні**
Фільтр не потрапив у `queryKey`. Дивіться Devtools: там має бути новий запис.

**Нескінченний цикл оновлень**
Реалізовано тримання фільтрів і в `useState`, і в URL, синхронізуючи їх через `useEffect`. Джерело правди має бути одне – URL.

**Кнопка «Показати ще» не зникає**
`getNextPageParam` повертає `null` замість `undefined`. TanStack Query вважає `null` валідним параметром сторінки.

**У списку дублі після швидких кліків**
Немає `disabled={isFetchingNextPage}`.

**Devtools не видно**
Пакет не встановлено або компонент не додано в `main.tsx` усередині `QueryClientProvider`.

**`useSearchParams` кидає помилку**
Компонент не всередині `<BrowserRouter>`.

**Список блимає при кожному поверненні**
`staleTime: 0` (значення за замовчуванням). Поставте більше значення.
